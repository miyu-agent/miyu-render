# Miyu render (miyu-render)

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This repository is Miyu's render package (id `render`). It renders Markdown into PNG images, including syntax-highlighted code, tables, formulas and Mermaid diagrams. It is mainly used by the chat platforms: when a reply is too long, the chat platforms package renders it into images and sends those instead; in the terminal UI and the web UI, you can also ask the AI to render images.

## Install

Install Miyu first, then run:

```sh
miyu pkg install render
```

Once installed, the package runs on its own; you do not need to open it or download a model. The package can be installed on `linux-x86_64`, `macos-aarch64` and `windows-x86_64`. Installing it adds the following:

- The AI tool `render_image`: it renders a piece of Markdown, or a `.md` file in the workspace, into images, saves them as files and returns the file paths.
- The bus method `render.markdown`: another package passes in Markdown and gets back the images page by page. This is the method the chat platforms package uses to turn long replies into images.
- The settings keys `render.theme`, `render.font`, `render.code_font` and `render.font_size`.

What it can render, where the images are stored, what each setting means, and what to do when something goes wrong are described in [Add-ons: Render](https://github.com/miyu-agent/miyu/blob/main/docs/en/guide/addons.md#render-render).

Rendering uses the fonts already installed on the system and never downloads fonts. If the system has no font that supports Chinese at all, rendering is not possible: on Linux, install Noto Sans CJK (for example the `noto-fonts-cjk` package).

## Development

The package is a Rust program, `miyu-render`, that talks to the core only through the protocol and does not depend on any of the core's crates. The package folder is `package/`, which holds only the manifest `package.toml`.

| Folder | Contents |
|---|---|
| `src/markdown/` | Parsing Markdown (with `pulldown-cmark`) |
| `src/render/` | Layout and drawing (with `cosmic-text` and `resvg`; formulas use `ratex`, with the KaTeX fonts compiled into the program; Mermaid uses the copy in the core repository's `third_party/mermaid-rs-renderer`, pinned to one commit in `Cargo.toml`) |
| `src/fonts/` | Picking system fonts: on Linux it queries `fontconfig`, and on macOS and Windows it uses the default font names |
| `src/tools/`, `src/methods/` | The tool `render_image` and the bus method `render.markdown` |
| `tests/protocol.rs` | Starts `miyu-render serve` and talks the protocol to it the way the core does |
| `tests/fonts/` | Fonts for the tests, trimmed and renamed; their sources and licenses are in `tests/fonts/README.md` |
| `docs/prompt-ledger.md` | The register of text the model sees (tool descriptions, parameter descriptions, tool results) |

The tests do not depend on the fonts installed on the computer running them; they only use the fonts in `tests/fonts/`.

Development needs Rust; the version is the one in `rust-toolchain.toml`, and `rustup` installs it automatically. CI (`.github/workflows/ci.yml`) runs these checks on Linux, macOS and Windows:

```sh
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --document-private-items --locked
cargo test --locked --no-fail-fast
```

In addition, every `.rs` file must be no longer than 500 lines, and test files count too.

To try an install on your own machine, put the built program into `bin/` in the package folder, then copy the package folder to a folder named `render` and install it (the package id is taken from the folder name):

```sh
cargo build --release --locked
mkdir -p package/bin
cp target/release/miyu-render package/bin/
cp -R package /tmp/render
miyu pkg install /tmp/render
```

On Windows, the program's file name ends in `.exe`. To publish a new version, push a `v<version>` tag; `.github/workflows/release.yml` builds one `.miyu` file for each system and uploads it to the release. The tag's version must match `version` in `package/package.toml` (change the version in `Cargo.toml` along with it).
