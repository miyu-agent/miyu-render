## 施工单 R-14：宽表放宽栏，表头只在空格处折

状态：做完了（2026-11-26）。

### 目的

2026-11-26 项目主人看了一张六列的表（几个 AI 程序的启动、内存、CPU 对比），指出表头的换行不对：
- 「启动中位数」断成「启动中 / 位数」，「空闲 CPU / 分钟」断成「空闲 / CPU / 分 / 钟」。
- 正文里「opencode」劈成「openco / de」，「125.7 ms」「384.5 MiB」的单位掉到下一行。

主人的判断：图片的栏宽受限。

### 根因

- 一栏写死 960（`COLUMN`，同旧版）。这张表六列，正文里最长的那个数连单位加上格子留空，每列要 165 到 180，光拆不开的就超过 960，只能逐字劈。
- 分列宽时表头也按整行不折量。表头整行比正文宽，几列一起超，被削成一样宽，窄的「程序」列也分到一样多。
- 排字照 Unicode 的断行规则：中日韩的字之间、数和单位之间的空格都能断，一个词比格子宽时逐字劈（`WordOrGlyph`）。

### 做什么

项目主人选「A 和 C 一起做」，上限 1600。

- **A. 宽表放宽栏**（`render.rs` 的 `column_for`，`table::needed`）：
  - 先量每张表正文不折行要多宽（表头只算它拆不开的那一段），这张图一栏照最宽的那张表放宽，最多 `MAX_COLUMN` 1600；普通的回复照旧 960。
  - 栏宽经 `Look.column` 交给排字、表格、公式、mermaid，画的时候经 `draw::block` 的 `(left, top, width)`，页宽经 `pages::size`、`pages::plan`。
- **C. 列宽三档、哪里不许断**：
  - `table/widths.rs`：每列量三个宽（拆不开的、正文不折的、连表头都不折的，`Need`）。连表头都不折放得下就照它给，富余照字多少分；放不下先让表头折，再让正文折，每一档都照一条上限线削最宽的几列，每列不少于低一档的宽。
  - `table/glue.rs`（新）：数后面的空格、下一个字是字母或 `%` 的换成不断行的空格（U+00A0）；表头里连着的中日韩字之间垫不断行的连接符（U+2060，不占宽），表头只在空格处折。
  - `layout.rs` 的 `narrowest`：照能断的地方都断开排一遍（`Wrap::Word`），量拆不开的那一段多宽。

### 测试

- `table/widths/tests.rs`：
  - 旧的四条照新签名改。
  - 新三条：表头先折、正文不折；正文也放不下时每列不少于拆不开的宽；宽裕的表一个字都不折。
- `table/glue/tests.rs`：数连单位、表头连着的中文垫连接符（跨段也垫）、正文的中文不垫、别的空格不动。
- `table/tests.rs`：
  - 那张表截几行：正文不折要的宽超过 960，放宽到它以后正文每格一行，表头的「分钟」「中位数」不劈开。
  - 一列长句子、三列带单位的数：让出来的是长句子，数连单位一行。
- `render/tests.rs`：宽表把页宽放宽、超宽的照上限 1600、窄表照旧 960。
- `pages/tests.rs`：页宽跟着栏宽走。

  - 连接符不显示成方块。
